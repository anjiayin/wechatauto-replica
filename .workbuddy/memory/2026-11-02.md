## 微信客服系统（kefu-system）开发完成

- 基于 wechatauto-replica（微信 4.x DB 解密读取 + UIA/OCR 发送）改造为「微信商机监测与客服系统」。
- 流程：产品经理 PRD → 用户确认决策（OpenAI 兼容接口 / 本机单进程 Web 应用 / 回复时自动前置微信窗口 / 5 分钟合并窗口 / 上百会话规模 / 判定严格度三档可配 / 仅系统内提醒 / 数据永久留存）→ 架构设计 → 工程师实现 T01–T05 → QA 两轮测试。
- 技术栈：FastAPI + Uvicorn + 原生 sqlite3（WAL+RLock）+ openai SDK v1（base_url 可配）+ Fernet 加密 Key；前端 Vite + React18 + MUI5 + react-query，dist 由 FastAPI 静态托管。
- 架构：Listener 回调 → Aggregator（会话+发送人 5 分钟缓冲）→ 有界队列(500) → 2 worker（预筛可选、三档严格度 Prompt、min_confidence 代码侧过滤、退避重试 2 次）→ 落库 → WS 推送前端。GUI 发送走独立串行 Sender 线程，三重校验 + 窗口前置。
- 位置：`kefu-system/`（后端 app/、前端 frontend/、docs/、tests/），未修改 wechatauto/ 与 adapter/。
- 测试：pytest 61/61 通过（含 API 契约、生命周期、并发边界）；QA 发现并已修复 2 个 Bug（main.py JSONResponse 参数错误、requirements 缺 uvicorn[standard] WebSocket 依赖）。
- 启动：`cd kefu-system && python run.py`（需微信已登录）；前端改代码后 `npm run build`。

## BugFix：消息查询恒为空（底座库回归缺陷）

- 现象：消息浏览页所有会话显示"暂无消息或读取失败"；API /api/messages 返回 []。
- 排查：API→wechatauto 层逐层复现，`WeChatDB().get_messages('filehelper')` 主/子线程均返回空；`_find_msg_tables` 命中 9 分片但 `_msg_conn` 返回 None。
- 根因：`wechatauto/db.py` `_msg_conn()` 成功路径缺少 `return found`（v1.2.0 重构引入），所有消息读取/监听增量取数恒为空。
- 修复：在 `if not found: return None` 之后补 `return found`（唯一改动）；核对唯一调用方 `_run_msg_query` 契约一致。
- 验证：get_messages('filehelper') 返回 3 条真实消息；kefu-system pytest 61/61；服务端 /api/messages/filehelper 返回非空。
- 注意：用户需重启 kefu-system 服务（修复前启动的旧进程仍加载旧代码）。
