### Bug 1：商机抓取误取配置前历史消息
- **现象**：P0 全新目录配置群聊后，把 2022 年历史消息全抓进商机分析，队列打满。
- **真因（源码核实）**：wechatauto Listener 用 `sort_seq` 做 watermark，与「配置时刻」无关；本系统 `start()` 用 `add_listener`（非 add_all/fast_init，全仓零处 add_all），而 `add_listener` 无法传起始水位。三条真实回放路径：①首次注册 `get_messages(limit=1)` 返回空（全新目录冷启动易触发）→ watermark=0；②`load_watermarks()` 灌入偏旧 sort_seq；③`_poll_once` 连续失败 3 次回退 0。
- **修复**（`monitor_since` 独立数值列，不复用 created_at）：
  - `db.py:121` monitor_targets 新增 `monitor_since INTEGER NOT NULL DEFAULT 0`（配置时刻 epoch 秒，0=存量不限制）；347-350 挂 `_migrate_add_columns` 幂等迁移；各 SELECT/insert DAO 补字段；586-597 新增 `reset_target_monitor_since()`。
  - `api/router_targets.py`：create 落库写 `int(time.time())`；update 仅 disabled→enabled 刷新（was_enabled 判定，已启用重复 PATCH 不刷新）。
  - `wechat_service.py:400-453` `_is_before_monitor_since()`，465-469 在 `_on_message` 最开头拦截（早于 skipped 日志/群名片/语音/图片入队）。兼容秒/毫秒 create_time（>1e11 归一）。
- **决策记录**：created_at 是 UTC 文本、消息是 epoch 秒，复用会在热路径引入文本→时间转换和时区歧义（项目铁律踩过 TEXT memcmp 误删整日数据的坑）；且水位需在停用→启用刷新，与「记录创建时间」语义冲突 → 保留独立数值列。
