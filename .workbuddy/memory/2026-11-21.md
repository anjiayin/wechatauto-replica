## wechatauto 逆向分析（REA 专家会话，只读+工具脚本）
- 用户授权确认（开源许可/功能学习研究/仅声明用途）后，对 wechatauto 做机制分析，全部基于源码静态证据 + 本机文件实证。
- 关键结论沉淀：
  - 社区工具导出 `x'<64hex key + 32hex salt>'` 是**每库 48B raw key**，而 keys.json 的 value 只存 **32B 裸 key**（`db.py:992-995`），不能直接写入——须拆 key、用 salt/HMAC 反查库相对路径作 key。
  - 项目内置 `derive_keys_from_master(master_hex)`（`db.py:774-798`，PBKDF2-HMAC-SHA512 256000，库头 salt，KDF_ITER=256000 @ `db.py:689`）可从 32B 主密钥派生全部库密钥；构造 WeChatDB(master_key=...) 即自动写盘（`db.py:702-706`）。
  - salt = 库文件头前 16 字节；本轮实证：三个账号的同名 contact.db salt 各异，仅目标账号 `wxid_hu7azjb674f721_ac0e` 的 key HMAC=True，证明 salt 反查可精准区分账号。
  - 页1 HMAC 校验 `db.py:268-289` 是唯一金标准（错一个只影响单库，fail-safe）。

## wx_key 社区工具机制对比（GitHub 源码实证，非猜测）
- 用户称其他社区工具已失效，仅 https://github.com/zj1123581321/wx_key 还在（已"永久停止更新"，README/仓库仍在）。实际作者规范仓库名是 `ycccccccy/wx_key`（README 里 Releases/clone 均指向 ycccccccy，zj1123581321 是同类镜像/搬运）。
- 机制本质区别（抓 C++ 源码确认，非 README 猜测）：
  - **wechatauto = 事后只读内存扫描**：`ReadProcessMemory` 扫 Config.Cipher 字符串→对象结构偏移取密钥 / cfg 主密钥 movabs 立即数（`db.py` 锚点）。不改目标内存。
  - **wx_key = 运行时主动 hook 函数**：`wx_key/src/hook_controller.cpp` 用版本特征码 `VersionConfigManager` 三档（>4.1.6.14 / 4.1.4~4.1.6.14 / <4.1.4）在 `weixin.dll` 定位目标函数机器码，`remote_hooker.cpp` 装 Inline Hook（硬件断点+VEH 代码在 `remote_veh.cpp` 但目前 `EnableHardwareBreakpointMode(false)` 未启用），拦截函数参数里 32B 密钥，`OnDataReceived` 校验 `dataSize==32` 经 IPC 回传。还用间接系统调用 `syscalls.cpp` + 堆栈伪造规避检测。装好 hook 后提示"现在登录微信"——密钥在登录瞬间被拦截。
- 互补性结论（关键）：两者**都依赖版本特征码/偏移**，都会受微信版本升级影响；但锚点目标不同（内存对象布局 vs 函数机器码），故失效不完全同步。wechatauto 因对象结构改版失效时，wx_key 函数机器码 hook 可能仍有效；反之亦然。但有三类共同失效：①微信升级超出 wx_key 配置表最高档且它已停更无人维护；②加密/派生规则改变（两者 key 都过不了页1 HMAC）；③真正旧版本内存结构大改。另注 wx_key 侵入式 hook（写内存/装 hook）比 wechatauto 只读扫描风险高（崩溃微信/杀软），且需登录瞬间拦截，体验更重。

## import_wechat_keys.py 增强（wx_key 用户场景）
- 新增 `--probe <64hex>` 自动识别密钥类型：先当主密钥 PBKDF2 派生（build_from_master），命中多个库则 kind=master；否则当单库裸密钥逐库 HMAC，命中则 kind=single；都失败 kind=unknown。解决"wx_key 导出的 32B 不知是主密钥还是单库密钥"的试错问题。
- 新增安全保护：result 为空时 **拒绝写入**（exit 3），避免错误密钥覆盖已有可用 keys.json。
- wx_key 拿到密钥后无需微信保持运行（脚本只读 db_storage 的 .db 文件头）。
- 自测：单库密钥 probe→正确识别 single 且 HMAC 1/1；错误密钥→unknown + exit3 + 不写文件 + 不覆盖已有文件；py_compile OK。（主密钥路径复用上一轮已验证的 build_from_master）
- 典型命令：`python tools/import_wechat_keys.py --probe <64hex> --dbstorage "E:\xwechat_files\wxid_xxx_xxxx\db_storage" --out "kefu-system\data\wechat_cache\keys.json" --verify`
