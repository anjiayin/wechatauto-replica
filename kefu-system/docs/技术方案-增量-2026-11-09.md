# 技术方案·增量 2026-11-09（微信客服/商机监测系统）

依据：`docs/PRD-增量-2026-11-09.md`（13 项反馈）。技术栈不变：后端 FastAPI + sqlite3(WAL) + openai SDK（`app/`），前端 Vite + React18 + TS + MUI5（`frontend/src/`）。不改动核心识别链路（pipeline/analyzer 主体），全部为增量字段、端点与渲染优化。

## ① 增量设计要点

### 1. analysis_logs 索引（P0）
`db.py` 建库/迁移处新增两条索引，幂等（`CREATE INDEX IF NOT EXISTS`）：
- `idx_analysis_logs_created_at ON analysis_logs(created_at DESC)`（日志页时间倒序）
- `idx_analysis_logs_session_time ON analysis_logs(session_username, created_at DESC)`（按群查询）
验证：`EXPLAIN QUERY PLAN` 无 `SCAN` 全表扫描。opportunities 现有索引不动。

### 2. 发送人取名链重构（P0，PRD 5/6/7）
位置：`app/wechat_service.py`。统一函数：
```
resolve_display_name(username, chatroom_username=None) -> str
# 优先级：我对该好友的备注 → 群内显示名 → 群昵称(get_group_members) → wxid
```
- `get_display_name` 内部改走此链；`_fetch_messages_once` 返回的上下文消息中发送人字段同样调用（查不到名称才回退 wxid 并截断）。
- `extract_content_sender(content)`（签名已核对：`@staticmethod`，`content -> str`）只负责提取 wxid，不做取名；取名交给 `resolve_display_name`。
- 历史快照不迁移：仅影响新写入/新查询展示（前端实时取名，存储仍存 wxid 与解析名两列则展示层统一走取名链）。

### 3. 图片消息渲染（P1 占位 / P2 真图）
- P1：前端 `OpportunityDetail.tsx` 对 type=img 渲染占位卡片（图标 + "[图片]"），上下文同理。
- P2：后端新增 `GET /api/opportunities/{id}/images/{local_id}`：调用底层 `wechatauto/media.py` 的 `MediaDownloader.download_image(user, local_id, save_dir)` 解密 .dat，服务端解密后缓存至临时目录并回 `image/jpeg`；本地无缓存时返回 404（不做网络拉取，主理人已定）。群聊仅有缩略图缓存时返回缩略图并在前端标注"缩略图"。
- ⚠️ `download_image` 调用细节（user 参数取值、save_dir 约定、解密 key 来源）**由工程师对照 `wechatauto/demo_media.py` 核对后实现**，本方案不锁定参数细节。

### 4. token 记录与迁移（P1，PRD 13）
- `analyzer.py` 在拿到 `resp.usage` 后随结果回传 `prompt_tokens` / `completion_tokens`。
- `analysis_logs` 加两列 `prompt_tokens INTEGER` / `completion_tokens INTEGER`，用 `ALTER TABLE ... ADD COLUMN` + PRAGMA 检查列存在性的幂等迁移（模式参考已核对的 `_migrate_opportunity_status_handled`：先查 schema，已存在则跳过；建库 DDL 同步补列）。

### 5. 全部已读（P2，PRD 12）
- 新增 `POST /api/opportunities/read-all`：`db.py` 批量将未读商机置已读，`notifier.py` 清空未读集合并广播（现有 WebSocket 广播机制复用）。
- 前端 `App.tsx` 顶部加"全部已读"按钮，全局一键、**无需二次确认**（主理人已定）。详情页清除规则文案照现行"点开即清除"。

### 6. 前端变更（P0/P1/P2 集中）
- `OpportunityList.tsx`：买卖货方向彩色 Chip + 筛选；群名/发送人列悬浮复制图标（`navigator.clipboard`，提示"已复制"）；消息原文列单行省略 + MUI Tooltip（长文本可换行）。
- `OpportunityDetail.tsx`：XML → 友好卡片；图片占位/真图渲染。
- `SettingsPage.tsx`：两表保留时长配置（下拉 + 自定义天数）；AI 单价输入 + 单位切换（元/千 vs 元/百万）。
- `App.tsx`：顶部状态栏对比度修复——正常绿底白字、异常红底白字，明暗主题都校验；加"全部已读"。
- `api/client.ts` + `api/types.ts`：新增端点封装与类型。

### 7. 非文本消息 XML 摘要（P1）
后端新增 `app/content_format.py`：`format_content(msg_type, xml) -> str|dict`，支持链接（title/description/url）、小程序、表情包占位；解析失败回退类型名占位（如 `[链接]`），任何场景不透传原始 XML。商机存库与前端展示统一走该函数（在 pipeline 写库前格式化，详情页上下文同样调用）。

### 8. 买货/卖货方向（P1）
- `opportunities` 加 `direction TEXT DEFAULT 'unknown'`（buy/sell/unknown），幂等迁移同第 4 条模式。
- `analyzer.py` Prompt 的 JSON 输出增 `direction` 键（主理人已确认可接受轻微准确率影响）；规整函数兜底为 unknown。
- 历史不回溯、不补跑（主理人已定）。列表 Chip：买=蓝、卖=橙、不明=灰。

### 9. 历史数据管理（P1）
- `db.py` 新增 `delete_older_than(table: str, days: int) -> int`（返回删除行数，事务内执行，两表互不影响；table 白名单校验防注入）。
- 新增 `POST /api/system/purge {table, keep_days}`。
- settings 存 `retention.logs_days=90` / `retention.opps_days=365`；进程内每日 03:30 定时清理（`asyncio` 定时任务，启动时注册，miss 不补跑只记日志）；SettingsPage 提供"立即清理"按钮，清理结果写入日志并在 UI 反馈。

### 10. AI 账单（P1）
- settings 增 `billing.input_price` / `billing.output_price` / `billing.unit`（`per_k`|`per_m`）。
- 新增 `GET /api/system/billing?date=`：按日汇总 analysis_logs 的 token，费用 = tokens/单位换算 × 单价，返回今日/累计。
- 工作页（`App.tsx` 顶部）展示今日费用；SettingsPage 展示累计并配置单价。

## ③ 共享约定

1. **取名链**：统一入口 `resolve_display_name(username, chatroom_username=None) -> str`；优先级 备注→群显示名→群昵称→wxid（wxid 回退时前端截断展示）。`extract_content_sender` 保持 `content -> str` 签名，只提 ID 不取名。
2. **direction 取值**：`'buy' | 'sell' | 'unknown'`，DB 列默认 `'unknown'`，AI 缺失/非法值一律归 unknown，历史不回填。
3. **settings 键名**：`retention.logs_days`（默认 90）、`retention.opps_days`（默认 365）、`billing.input_price`、`billing.output_price`、`billing.unit`（`per_k`|`per_m`）。数值均为 float/int 字符串存 settings 表。
4. **迁移模式**：全部幂等——加列用 `PRAGMA table_info` 检查后 `ALTER TABLE ADD COLUMN`；加索引用 `CREATE INDEX IF NOT EXISTS`；表重建参考 `_migrate_opportunity_status_handled`（查 sqlite_master → 跳过已迁移）。迁移在 db 初始化时执行，失败不阻断启动但记 ERROR 日志。
5. **API 风格**：沿用现有 REST 约定（`/api/...`，JSON，复用现有错误处理）；清理与已读操作返回 `{table, deleted|updated}` 形式的计数。
6. **图片端点**：`GET /api/opportunities/{id}/images/{local_id}`，成功回 `image/jpeg`（StreamingResponse），无缓存回 404 + `{"detail": "no local cache"}`；实现前必须对照 `wechatauto/demo_media.py` 确认 `MediaDownloader.download_image(user, local_id, save_dir)` 的实参含义。

## ④ 待明确事项（≤3）

1. **多模型计价**：当前账单方案按单一单价估算；若 analyzer 实际混用多个模型，是否需要 per-model 单价？（建议先全局单价，日志已存模型名可后续拆分）
2. **图片缓存策略**：解密后临时缓存目录的位置与清理策略（建议放系统临时目录 + 进程退出清理），是否可接受每次请求重复解密（量小则不缓存）？
3. **定时清理可靠性**：进程内 03:30 任务在服务重启/长睡后可能错过当日窗口；是否接受"启动时若已过 03:30 且当日未清理则补跑一次"？
