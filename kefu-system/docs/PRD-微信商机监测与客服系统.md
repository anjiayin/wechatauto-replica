# PRD：微信商机监测与客服系统（基于 wechatauto-replica）

> 产出：产品经理 许清楚（software-product-manager）· 2026-11-02
> 状态：待用户确认

## 1. 产品定位与目标

本产品是基于开源项目 wechatauto-replica 的本地化「微信商机监测与客服系统」，面向需要从微信群聊/私聊中挖掘销售线索的个人或小团队（如机械加工、供应链、贸易等行业的业务员）。系统运行在用户的 Windows 机器上，复用项目已有的本地数据库解密读消息、秒级实时监听、UIA+OCR 发消息三大能力：用户配置要监控的群/好友与商机类型（自然语言描述）后，系统实时拉取新消息、调用用户自备的 OpenAI 兼容 AI 接口判定是否为商机，命中的消息进入商机列表，展示来源、发送人、时间、原文与 AI 提取的需求要点，用户可在系统内一键回复目标群/好友。核心解决的问题是：**从海量群消息中人工刷屏找商机 → 变成 AI 筛选 + 集中处理 + 快速回复**。

产品目标：
1. **实时商机捕获**：指定会话的新消息秒级进入分析管线，商机从产生到可见延迟 ≤ 30 秒（AI 响应时间除外）。
2. **可配置的商机判定**：商机类型以自然语言描述配置，无需改代码即可新增/修改商机类别；AI 接口（地址/Key/模型）全部可配置。
3. **闭环处理**：商机列表 → 详情 → 人工回复（复用发消息能力 + 三重目标校验防误发）形成完整工作流。

## 2. 用户故事

1. 作为业务员，我想在设置页从联系人/群列表中勾选要监控的群和好友并保存，以便只关注与业务相关的会话。
2. 作为业务员，我想用自然语言新增一条商机类型（如"寻找机械加工订单的采购需求"）并启用/停用，以便 AI 按我的业务口径判定商机，改口径不用等开发。
3. 作为业务员，我想配置 AI 接口的 API 地址、Key、模型名并点击"测试连接"，以便接入我自备的 OpenAI 兼容接口并确认可用。
4. 作为业务员，当被监控会话中出现商机消息时，我想收到系统内提醒（未读角标/声音），以便第一时间知道有新商机。
5. 作为业务员，我想在商机列表看到来源（群名/好友昵称）、发送人（群内昵称+wxid）、时间、AI 提取的需求要点摘要，以便快速扫一眼决定处理优先级。
6. 作为业务员，我想点开商机详情看到消息原文、上下文几条消息、发送人资料，以便判断商机真实性和紧迫度。
7. 作为业务员，我想在商机详情中直接输入内容回复该群/好友（支持文本、@群成员、引用回复），以便不用切换回微信窗口就能跟进商机。
8. 作为业务员，我想对 AI 误判的消息标记"非商机"，以便降低同类消息的重复打扰，并让列表保持干净。

## 3. 需求池

### P0（首版必须）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| P0-1 | 监控对象配置：选择/搜索会话（群与好友），启用/停用 | 能通过昵称搜索定位群/好友（复用联系人搜索、群名↔ID 转换）；配置持久化，重启后生效；可随时增删 |
| P0-2 | 实时监听接入：对启用会话注册 Listener 回调 | 新消息秒级进入分析队列；watermark 持久化，重启不重复推送旧消息；慢的 AI 调用不阻塞监听 |
| P0-3 | AI 接口配置：API 地址、Key、模型名、超时，支持连接测试 | 保存后立即生效；"测试连接"返回模型可用性；Key 本地加密存储不明文展示 |
| P0-4 | 商机类型配置：自然语言描述 + 启用开关，可增删改 | 至少支持多条商机类型并行；每次分析将启用的类型描述注入 Prompt；描述修改后对后续消息生效 |
| P0-5 | AI 商机分析（仅文本消息） | 对启用会话的新文本消息调用 AI；返回结构化结果（是否命中/命中类型/需求要点摘要/置信度可选）；非文本消息直接跳过并按未分析标注 |
| P0-6 | 商机列表页 | 列表项含：来源会话、发送人（群内昵称+wxid）、时间、AI 要点摘要；按时间倒序；支持按来源/类型筛选；数据本地持久化，重启不丢 |
| P0-7 | 商机详情页 | 展示原文、AI 提取要点、发送人资料；可查看该消息前后各 N 条上下文（复用历史消息查询） |
| P0-8 | 人工回复：在系统内对目标群/好友发送文本 | 复用发消息能力；发送前三重目标校验；支持 @群成员 与引用回复；微信窗口不可见/锁屏时给出明确失败提示而非静默失败 |
| P0-9 | 误报处理 | 商机条目可标记"非商机"（列表隐藏/降级，可查看已忽略项）；已回复状态标记 |
| P0-10 | 系统内通知 | 新商机产生未读角标 + 可选提示音；仅系统内提醒，不做外部推送（P1） |

### P1（第二批）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| P1-1 | 命中外部推送：企业微信/钉钉等 Webhook 推送 | 可配置 Webhook 地址；推送含来源、发送人、要点摘要；可开关 |
| P1-2 | 图片消息分析 | 支持配置是否分析图片：下载媒体 → 多模态模型判定（依赖用户 AI 接口支持视觉）；无法识别时标注原因 |
| P1-3 | 商机去重与合并 | 同一会话同一发送人短时间内的连续消息合并为一条商机；相似商机（同会话+同发送人+同类型）可合并展示 |
| P1-4 | 回复增强 | 发送文件/图片；快捷话术模板；回复前显示目标会话确认信息 |
| P1-5 | 消息流浏览 | 按会话浏览全部历史消息（复用数据库查询），不限于商机命中的消息 |
| P1-6 | 简单统计 | 按天/来源/类型的商机命中数统计，误报率（标记非商机比例）展示 |
| P1-7 | 历史消息补扫 | 可对指定会话最近 N 天历史消息补跑分析（复用历史消息查询能力） |

### P2（远期）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| P2-1 | AI 辅助回复草稿 | AI 根据商机要点生成回复建议草稿，人工确认后发送（仍非全自动） |
| P2-2 | AI 自动回复 | 可对特定会话开启自动回复，带频控与关键词白名单/黑名单；默认关闭并显著提示风险 |
| P2-3 | 多微信账号支持 | 多账号数据源切换与汇总（依赖多账号登录态管理，当前项目为单账号） |
| P2-4 | 语音消息分析 | 语音转文字后进入分析管线 |
| P2-5 | 商机跟进状态管理 | 商机流转：待处理/跟进中/已成交/已关闭，附跟进备注 |

**范围控制说明**：首版只做人工回复（P0-8），AI 自动回复放 P2；首版只分析文本消息，图片 P1、语音 P2。

## 4. UI 页面结构

形态：本地 Web 应用（浏览器访问 localhost），左侧全局导航，主区内容。

### 4.1 全局框架
- 左侧导航栏：商机列表（默认页，带未读角标）、消息浏览、设置；顶部：连接状态指示（监听服务运行中/微信登录态/微信窗口可见性）。

### 4.2 商机列表页（首页）
- 筛选栏：时间范围、来源会话、商机类型、状态（待处理/已回复/已忽略）。
- 列表：每行 = 商机类型标签 | 来源（群名/好友昵称）| 发送人（群内昵称 + wxid）| 时间 | AI 要点摘要 | 状态徽标。
- 交互：点击行进入商机详情；行内快捷操作：标记非商机、去回复。

### 4.3 商机详情页（或右侧抽屉）
- 上区：消息原文、AI 提取的需求要点、置信度/命中类型、时间与来源信息、发送人资料。
- 中区：上下文消息（前后各 N 条，可展开加载更多）。
- 下区：回复框——目标会话确认信息、文本输入、@群成员选择、引用回复开关、发送按钮；发送结果反馈（成功/失败原因）。
- 操作：标记非商机、标记已回复。

### 4.4 设置页（三个子页签）
- **监控对象**：会话搜索框 → 候选列表 → 已选监控列表（群/好友分组，各自开关）。
- **商机类型**：类型列表（名称 + 自然语言描述 + 启用开关 + 编辑/删除）；新增表单；描述示例。
- **AI 接口**：API 地址、API Key（掩码显示）、模型名、超时时间、温度（可选）；"测试连接"按钮与结果反馈。
- 所有设置保存即时生效并持久化。

### 4.5 消息浏览页（P1，首版可只读简化版）
- 左侧：会话列表（可搜索）；右侧：所选会话的消息流（时间正序）。

### 4.6 运行前提提示（贯穿全局）
- 微信未登录 / 窗口被遮挡 / 锁屏导致发送不可用时，全局横幅提示"发送功能暂不可用"；商机监听不受影响（监听为本地数据库读取）。

## 5. 待确认问题

1. **AI 接口格式**：是否为 OpenAI 兼容（`/v1/chat/completions`）？是否需要多模态（P1 图片分析依赖视觉模型）？是否需要多接口备用？
2. **部署形态**：本机单进程 Web 应用，还是"采集机与查看端分离"（沿用 adapter/ 的 WebSocket 广播模式）？
3. **发送可用性预期**：回复依赖微信窗口可见且未锁屏。是否接受"监听 7×24，回复需电脑在线且微信窗口可见"？是否需要发送前自动把微信窗口带到前台？
4. **商机去重/合并策略**：同一人连续多条消息是否合并？合并窗口多长？多类型同时命中如何展示？
5. **命中通知方式**：首版仅系统内通知是否够用？P1 外部推送优先渠道（企业微信机器人 / 钉钉 / 邮件）？
6. **数据留存**：商机记录与原始消息留存多久？是否需要导出（CSV/Excel）？
7. **多微信账号**：是否单账号监控（建议首版单账号）？
8. **合规确认**：消息内容会发送到自备的第三方 AI 接口，需用户知情接受（设置页一次性确认）。
9. **监控对象规模**：预计同时监控多少个群/好友？影响 AI 调用频率与成本。
10. **商机判定严格度**：宁多勿漏还是宁缺勿滥？是否暴露"严格/宽松"档位或最低置信度门槛？
